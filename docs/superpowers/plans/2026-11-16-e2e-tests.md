# E2E tesztek (CodeceptJS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Böngészőben végigkattintott E2E tesztcsomag az F1Tipp-re, saját `e2e` Symfony-környezettel és külön `f1tipp_e2e` adatbázissal.

**Architecture:** Az nginx egy második server blokkon (`http://127.0.0.1:8001`) `APP_ENV=e2e`-vel szolgálja ki ugyanazt a PHP-konténert. Két, csak `e2e`-ben futó konzolparancs (`app:e2e:reset`, `app:e2e:scenario`) építi fel az adatbázist relatív időpontú eseményekkel. A `tests/e2e/` alatti CodeceptJS projekt (Playwright helper) egy saját helperen át hívja ezeket `docker compose exec`-kel, majd a UI-on végigkattintja a szenáriókat.

**Tech Stack:** Symfony 5.4 / PHP 7.4 (Docker), MySQL 5.6, CodeceptJS 3.x + Playwright (Chromium), Node 22 a hoston.

**Spec:** `docs/superpowers/specs/2026-11-16-e2e-tests-design.md`

## Global Constraints

- Az e2e futás nem módosíthatja a `f1tippelek` (dev) adatbázist, a dev cache-t és a `.env.local`-t.
- A seed/reset parancsok csak `e2e` kernel-környezetben futhatnak; más env-ben hibakóddal (1) kilépnek, és semmit nem csinálnak.
- A tesztelt lépést mindig a UI-on kell végigcsinálni. Előfeltételt seedelni szabad.
- Időzítés miatt nincs fix `I.wait(n)`. Állapotra várunk (`waitForText`, `waitForElement`, `waitInUrl`). Kivétel: a határidő lejártának kivárása a szerver által adott időponthoz (Task 7).
- Termékkód-változtatás csak `data-test` attribútum, `FileCache` útvonal és konfiguráció lehet.
- Ha egy teszt valódi alkalmazáshibát talál: a teszt piros marad, vagy `Scenario.skip` kerül rá `// BUG: …` megjegyzéssel, és a hibát jelezni kell a usernek. Az appot nem javítjuk.
- A pontszabályok a `design27` szerintiek: időmérő 4/1, futam 3/1 + SC 3, sprint 1/0, helyezési pont 14/10/8/7/6/4/3/2/1/0.
- A konzolparancsok mindig így futnak: `docker compose exec -T -u www-data -w /var/www/f1tipp_sf4 php php bin/console <cmd> --env=e2e`. A `www-data` user azért kell, hogy a cache-fájlok az FPM számára írhatók maradjanak.
- Commitba nem kerülhet: a `.env` és a `docker-compose.yml` meglévő lokális módosításai (DB-név), a `docker-compose.override.yml`, valamint az untracked dev fájlok (`event*.sql`, `ver_full.png`, `.playwright-mcp/`, `download_drivers.py`, `assets/images/drivers/`, `src/Controller/Api/`, `CLAUDE.md`). Csak a nevesített fájlokat kell stage-elni.
- Branch: `e2e-tests`.

## Review Focus

1. **Óraeltérés a host és a PHP-konténer között.** A határidő-teszt rossz pillanatban küldhet. Ezért a scenario parancs JSON-ban visszaadja a `serverNow` és a `deadline` epoch-értékét, a teszt pedig ezekhez képest vár (Task 3, Task 7).
2. **Bennragadt Doctrine result cache két szenárió között** (`…ActualWeekendEvents`, `…NextEvent`, `…Remain`). A következő teszt az előző hétvégét látná. Task 7: egymás után futó `open-weekend` → `deadline-passed` szenárió más füleket mutat.
3. **A reset véletlenül a dev DB-n fut le.** Task 2: a guard-teszt `--env=dev`-vel 1-es kilépési kódot ad, és a `f1tippelek` sorainak száma változatlan.
4. **A root-ként létrehozott cache-fájlokat az FPM nem tudja írni.** Ilyenkor 500 jön. Task 4 smoke: reset után a `/` 200-at ad, és a konzolban nincs hiba.
5. **A teljes futás a dev adatbázist is érinti.** Task 12: a `f1tippelek` tábláinak sorszáma a futás előtt és után azonos.
